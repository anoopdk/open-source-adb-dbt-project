# Problem statement

## Client context

- **Delivery organisation:** Zynx Technologies Ltd
- **Domain client:** Logistics Client
- **Engagement type:** Reference Implementation Delivery

## Business problem

The Logistics Client needed a modular lakehouse pattern that separates heavy distributed ingestion/cleansing (PySpark) from declarative analytics modelling (dbt), so platform and analytics engineers can own layers independently.

## Success criteria (engagement)

- Clear architecture and ownership model
- Inspectable artefacts in Git (docs, diagrams, code/notebooks)
- Domain-safe documentation suitable for public portfolio audit
- Handover path for client engineering teams
